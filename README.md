# 吃了吗 (Fork-Cast)

零标签随性就餐决策工具。无需为菜品打标签或维护复杂分类，直接输入当前状态或心情大白话（如“淋雨了想喝热腾腾的汤”、“胃不舒服拒绝油腻”），基于 **Jev System 1 概率决策模型** 从个人候选池中快速拍板今天吃什么。

---

## 核心特色：以 Jev 为核心的 System 1 决策

本项目区别于传统大语言模型（LLM）的“漫长文字生成与模糊玄学 Prompt”，核心完全依托 **Jev 结构化决策引擎**：

- **原生校准概率，不做无谓生成**  
  Jev 直接输出严格校准的抉择概率分布（Calibrated Choice Probabilities）与置信度，直接通过数学边际定夺最优解，杜绝 LLM 冗长的寒暄与套话。
- **并发原子原语门控（Single-Shot Concurrent Primitives）**  
  单次决策周期内并发执行三组原子判定：
  - `Choice` 原语：对动态候选池执行多分类概率分布测算；
  - `Noul` 可行性断言：识别诉求是否自相矛盾或超越候选池能力极限；
  - `Noul` 冷淡度断言：敏锐捕捉“吃啥都行、随便”的无偏好心理。  
  三者并发裁决，彻底解耦语义冲突检测与候选池规模，毫秒级响应。
- **四种数学自适应裁决**：
  - 🎯 **拍板落定 (Decisive Pick)**：首选优势显著、置信度高时一击定音，并附带置信度与备选项。
  - ⚔️ **势均力敌 (Dilemma Duel)**：两到三个候选概率难分伯仲时触发单次决战，拒绝反复掷骰纠结。
  - 🚫 **神仙难救 (Impasse)**：当诉求自相矛盾（如“既要吃滚烫热汤又要吃冰爽冷饮”）时直接判决无法实现，提示冷静重想。
  - 🎲 **随缘盲盒 (Blind Box)**：识别到用户彻底漠不关心时直接切入独立盲盒抽签，不污染真实用餐历史。
- **动态状态上下文注入 (State Context)**  
  自动将用餐时段、近期用餐历史（防腻降权窗口）与单次临时排除列表打包注入 Jev 状态，实现更贴合生理节奏的推演。

## 其它交互特性

- **隐式记忆与单步撤销**：被采纳的拍板与决斗结果自动计入历史并在后续决策中防腻降权；如果不满意可一键撤销并临时排除。
- **打卡机风格单页界面**：复古出票动效，完全适配手机与桌面，支持直接在网页端管理候选池与 Key。
- **开箱即用 Mock 兜底**：未配置 API Key 时系统内置 Mock 引擎，可直接体验完整决策链路。

## 配置说明

项目支持**离线体验**与**真实 Jev 裁决**两种模式：

- **离线体验**：无需配置 Key，默认自动进入 Mock 模式。
- **接入 Jev 服务**：
  - 复制配置文件：`cp .env.example .env`
  - 在 `.env` 中填写 `TYPESAFE_API_KEY`（支持 TypeSafe 官方或 Vercel AI Gateway）。
  - 也可在网页右上角「设置」中直接输入个人 Key（BYOK 模式）。

### 核心参数

| 变量名 | 默认值 | 说明 |
| :--- | :--- | :--- |
| `TYPESAFE_API_KEY` | 空 | Jev 模型调用 Key（留空则进入 Mock 模式） |
| `TYPESAFE_BASE_URL` | `https://api.typesafe.ai` | 模型网关地址（支持 Vercel / Cloudflare 自建网关） |
| `JEV_MODEL` | `jev-latest` | Jev 决策模型版本 |
| `HISTORY_WINDOW_HOURS` | `48` | 用餐历史防腻回溯窗口（小时） |
| `PORT` | `8000` | 服务端口 |

## 候选就餐清单维护

默认候选池位于 `data/candidates.json`。你可以直接在前端「设置」中增删，或手动编辑该 JSON 文件添加常吃的店名或菜品。
